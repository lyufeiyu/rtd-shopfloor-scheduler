# 智能排产工作台

## 本次可用功能

- 生产工作台采用深蓝绿导航、浅色卡片，正文 15–16px、辅助信息 13px；“当前数据集”“排产范围”“方案偏好”使用 16px 粗体。表格保留横向滚动，小屏上下布局。
- 排产进度由后台工作进程报告：排队、数据读取、工站排产、约束核验、结果导出、完成。工站阶段按已完成工站分配进度权重，不表示剩余时间；成功状态才显示 100%，失败保留最后进度和错误提示。
- 轮询只更新进度区，避免打断输入。任务完成后提示查看方案，不自动切走正在使用的页面。
- 刷新会恢复最近的数据集和任务；历史数据继续保存在本机。
- 排产助手按当前数据给出风险清单、策略说明和未排原因计数。每份分析标注数据集或任务来源。
- 输入“WF 工站快速生成”“为 WF 工站生成均衡优化方案”或“全部工站均衡优化”，可生成配置草稿。点击“应用到排产配置”后核对范围与偏好，再点击“生成排产方案”。

## 当前边界

当前助手是本地规则实现，未调用 LLM，不会上传生产数据到外部服务。它只理解一个工站或全部工站，以及快速或均衡策略。出现未知工站、多个工站、冲突偏好或额外约束时，会要求重新描述，不会悄悄丢掉额外要求。

目前不能通过对话修改交期、插单、维修、设备状态或现场控制。已有工艺资格、芯片限制、在制占用与维修窗口仍由排产引擎核验。方案应经现场人员复核后使用，系统没有实现生产指令下发、审批签名、MES 同步或实时数据采集。

## LLM 在后续落地中的职责

1. 需求澄清：把自然语言转为可审阅的结构化需求，缺少范围、目标、时间条件时主动追问。
2. 工具调用：通过后端受控接口读取数据诊断、生成配置草稿、查询任务、解释结果。LLM 不直接修改 Excel、SQLite 或设备状态。
3. 方案解释：引用任务编号、指标和未排原因，说明建议的依据；没有数据支持时明确说明。
4. 生产异常辅助：在实现相应排产约束与重新排产接口后，才开放插单、停机等场景。先展示影响范围，再由调度员确认。

接入前需确定企业可用的模型服务、部署方式、生产数据出域规则及凭证管理方式。凭证仅放在服务端；接口返回的工站和策略必须再次经过现有后端白名单校验。真正的交期优化与插单不能仅靠提示词，需要同步扩展算法和验收数据。

## 验证

使用安装了 requirements.txt 的 Python 运行：

```powershell
py -3 backend/check-progress.py
```

测试在临时存储中启动独立服务，上传项目示例工作簿，执行 WF 快速排产，检查真实进度单调递增、最终完成和结果约束校验。不会修改正式历史任务。

本次另在浏览器中验证了配置草稿生成与应用，以及 WF 均衡优化任务。该浏览器验收任务会保留在正式任务记录中，便于回看。
